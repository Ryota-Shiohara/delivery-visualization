# Webダッシュボード（担当D）

配送品質スコア・内訳・履歴、衝撃と傾斜の時系列、走行軌跡・注意地点・路面評価を表示します。

- データは参照APIから取得し、ブラウザからDynamoDBへ直接接続しない。
- 表示中は5秒間隔（取得完了後）で配送一覧と読み込み済み範囲の路面区画を取得する。配送詳細は一覧のsummary.updatedAtと集計値を比較し、新規・変更された配送だけ再取得する。選択中・全配送で同じキャッシュを利用し、一覧と選択中の詳細の重複取得を避ける。タブへ戻ったときやネットワーク復帰時も同じ判定を行う。通信失敗時は前回の表示を保持して再試行する。
- 索引の反映遅れに備えて初回・更新検出後は10秒後に一度再確認し、その後も各配送の前回取得から60秒以上経った自動更新で再取得する。日時が欠けた配送は毎回取得する。「更新」ボタンとデータセットの切り替えではキャッシュを破棄する。全配送一覧から削除された配送の軌跡とキャッシュも除く。
- 配送詳細は先頭・末尾の計測を取得し、その間を最大50の時間帯に分割して各時間帯から約10件ずつ、合計最大500件を取得する。再取得時も全区間から抽出し、検索・配送選択・明細ページ・地図の表示位置を保持する。
- 各時間帯では先頭側から取得し、空区間や取得枠未満の区間の余りは補充しないため、500件未満になる場合がある。時間に対する配分であり、計測件数に対する一定割合の抽出ではない。抽出だけでは衝撃やピークが取得されない場合があるため、衝撃は専用APIから補完する。スコア・衝撃回数などの集計値は配送全体の値を表示する。
- AWSでは全計測を読み取らず、時刻索引で両端を各1件、各時間帯を1ページだけ取得する。最大52回のQueryを、時間帯については最大4並列で実行する。軌跡用にDBから受け取る計測は合計最大500件で、衝撃の全件取得分は別。小規模データでも問い合わせ回数による負荷は発生する。
- 地図上部の「選択中の配送／全配送」で軌跡の表示範囲を切り替える。全配送モードではsummaryにある配送一覧の全ページを読み、各配送の最大500件の抽出軌跡を配送単位で2並列まで取得する。検索で非表示の配送も対象。GPSのない配送は取得件数に含め、地図には描画しない。
- 全配送の軌跡は配送ごとに線を分け、線・地点のポップアップに配送IDを表示する。スコア・グラフ・明細は左側で選択した配送のまま。取得進捗・GPSありの配送数を表示し、自動更新では地図位置を保つ。取得失敗時は前回の全配送の軌跡を保持する。初回の全配送取得は空区間も含め配送数に応じた通信・DBアクセスが発生する。
- GPS精度が悪い地点や測定不足の区画は参考値・未評価として表示する。
- 区画の測定回数・更新日時、比較する配送の条件を表示する。
- 区画はCの `avgScore`（0〜100、高いほど高評価）を使い、0.0005度の区画を赤→黄→青緑で塗るヒートマップとして表示する。密度や計測件数で色を変えず、隣の区画へスコアを補間しない。不透明度は初期35%、0〜75%で調整でき、軌跡・衝撃はヒートマップより上に描画する。
- 参考値は破線、スコア未取得の旧データは薄い灰色の破線で区別し、0点として扱わない。平均スコアはポップアップと路面区画一覧にも表示する。地図は読み込み済みの全区画が対象で、「路面区画の続きを読み込む」で範囲が増える。
- S3のHTTPSオブジェクトURLからの直接配信を採用。閲覧制限・公開範囲は `infra/` と連携する。

ローカル仮環境を実装済み。リポジトリ直下の `D担当_はじめに.md` を参照してください。Node.js標準HTTPサーバーと、ローカル保存したLeafletを使います。Cの共有例・架空デモ・JSON取り込みに対応します。AWS用の設定は `config.js` の `apiBaseUrl` と `deployment: "aws"` に指定します。S3配信とDynamoDBの共有例による仮表示を確認済みです。[AWS手順](../../docs/deployment/d-dashboard-aws.md)を参照してください。

配送単位のQuery・ページ取得・UI整理とCの索引追加は [既存環境の更新手順](../../docs/deployment/d-query-index-upgrade.md) を参照してください。

## 衝撃の全件表示

軌跡の最大500件の抽出に加え、衝撃専用APIの全ページを取得します。選択中・全配送の地図で、GPS座標のある衝撃を間引かず表示します。グラフと明細も取得した衝撃を補完し、同じmeasurementIdは重複させません。座標のない衝撃、全件取得の失敗、配送集計との反映差は画面に明示します。

AWSで利用するには、[衝撃専用索引の更新手順](../../docs/deployment/d-query-index-upgrade.md#衝撃を全件表示するための追加更新)に従い、解析Lambda・衝撃専用GSI・参照Lambda・画面を反映してください。コードの変更だけでは公開サイトは更新されません。
