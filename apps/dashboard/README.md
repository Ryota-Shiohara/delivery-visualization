# Webダッシュボード（担当D）

配送品質スコア・内訳・履歴、衝撃と傾斜の時系列、走行軌跡・注意地点・路面評価を表示します。

- データは参照APIから取得し、ブラウザからDynamoDBへ直接接続しない。
- 表示中は5秒間隔（取得完了後）で配送一覧・路面区画・選択中の配送を自動更新する。タブへ戻ったときやネットワーク復帰時も再取得する。通信失敗時は前回の表示を保持して再試行する。
- 配送詳細は先頭・末尾の計測を取得し、その間を最大50の時間帯に分割して各時間帯から約10件ずつ、合計最大500件を取得する。自動更新時も全区間から取得し直し、検索・配送選択・明細ページ・地図の表示位置を保持する。
- 各時間帯では先頭側から取得し、空区間や取得枠未満の区間の余りは補充しないため、500件未満になる場合がある。時間に対する配分であり、計測件数に対する一定割合の抽出ではない。衝撃やピークが取得されない場合がある。スコア・衝撃回数などの集計値は配送全体の値を表示する。
- AWSでは全計測を読み取らず、時刻索引で両端を各1件、各時間帯を1ページだけ取得する。最大52回のQueryを、時間帯については最大4並列で実行する。DBから受け取る計測は合計最大500件。小規模データでも問い合わせ回数による負荷は発生する。
- 地図上部の「選択中の配送／全配送」で軌跡の表示範囲を切り替える。全配送モードではsummaryにある配送一覧の全ページを読み、各配送の最大500件の抽出軌跡を配送単位で2並列まで取得する。検索で非表示の配送も対象。GPSのない配送は取得件数に含め、地図には描画しない。
- 全配送の軌跡は配送ごとに線を分け、線・地点のポップアップに配送IDを表示する。スコア・グラフ・明細は左側で選択した配送のまま。取得進捗・GPSありの配送数を表示し、自動更新では地図位置を保つ。取得失敗時は前回の全配送の軌跡を保持する。初回の全配送取得は空区間も含め配送数に応じた通信・DBアクセスが発生する。
- GPS精度が悪い地点や測定不足の区画は参考値・未評価として表示する。
- 区画の測定回数・更新日時、比較する配送の条件を表示する。
- S3のHTTPSオブジェクトURLからの直接配信を採用。閲覧制限・公開範囲は `infra/` と連携する。

ローカル仮環境を実装済み。リポジトリ直下の `D担当_はじめに.md` を参照してください。Node.js標準HTTPサーバーと、ローカル保存したLeafletを使います。Cの共有例・架空デモ・JSON取り込みに対応します。AWS用の設定は `config.js` の `apiBaseUrl` と `deployment: "aws"` に指定します。S3配信とDynamoDBの共有例による仮表示を確認済みです。[AWS手順](../../docs/deployment/d-dashboard-aws.md)を参照してください。

配送単位のQuery・ページ取得・UI整理とCの索引追加は [既存環境の更新手順](../../docs/deployment/d-query-index-upgrade.md) を参照してください。
