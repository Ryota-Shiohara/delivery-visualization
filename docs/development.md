# 開発・検証手順

## 準備

1. 授業環境のAWS権限・予算・期間を確認する。
2. スマホ実機でセンサ権限、HTTPS、取得頻度、画面消灯時の動作を確認する。
3. 言語・フレームワーク・構成管理ツールを選び、`decisions/` に記録する。
4. 共通データ・API・認証・エラー形式を合意する。
5. 選んだ構成に応じて依存関係、ロックファイル、実行・検証コマンドを追加する。

現時点では依存関係や起動コマンドはありません。

授業資料に基づく進行案は、1週目に各自のチュートリアルと構想・分担、2週目に構成図による説明と担当別開発、3週目に統合とデモ準備です。週・時限・発表時間の指定は2025年度概要資料によるため、2026年度の案内で確認します。詳しくは `course-requirements.md` を参照してください。

## 段階ごとの完了条件

| 段階 | 完了条件 |
| --- | --- |
| 最小構成 | 1台のスマホから送信した計測が保存され、Webで確認できる |
| 解析追加 | 配送品質の内訳と位置別振動を計算でき、再実行で重複加算されない |
| 統合検証 | 複数端末・複数走行の履歴、軌跡、注意地点、路面評価を表示できる |

## 検証内容

- 静止・傾斜・小さな段差で、検出結果と目視記録を比較する。
- 同じ経路を繰り返し走行し、ばらつき・欠測率・送信から表示までの遅延を記録する。
- 移動手段・固定方法・速度帯をそろえる。2台以上・各経路3回程度は初期目標とする。
- 再送、部分失敗、Streamsの再実行、GPS未取得・低精度、権限外のアクセスを確認する。

ローカルで再現可能な結合テストと、AWS環境・実機が必要な試験を区別して記録します。push・デプロイはこのリポジトリの作業ルールで禁止されています。
