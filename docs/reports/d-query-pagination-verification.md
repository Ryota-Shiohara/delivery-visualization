# 配送単位の取得とUI整理：検証記録

2026年10月12日。Windows PowerShell 5.1 / Node.js 24.21.0。

## 確認した変更

解析結果の全件Scanと累計5000件の停止処理を廃止。配送一覧はsummaryだけ、詳細はsummaryのGetItemとDeliveryTimeIndexのQuery、路面はcellだけを1ページ取得する。CとDの仮テーブル定義に同じ索引を追加。UIの開発用データ連携・C確認事項を削除した。

## 自動テスト

- Node.jsの入力・参照API・取得ページテスト24項目成功。
- DynamoDBをモックし、6001件を500件ずつ13回で、重複なし・欠落なしに取得。全体スコア92.5は再計算しない。
- 一覧が解析テーブルに触れない、詳細が配送IDの索引をQueryする、区画が別テーブルだけを読むことを確認。
- 壊れたcursor、他の配送/APIのcursor、限度外のlimit、空ページの続き、不存在404、索引不足503、権限不足500を確認。
- AWS CLIとHTTPSをモックしたD構築12シナリオ成功。既存Cテーブルに索引がない場合にAWSへの書き込み前に停止する。
- 既存のall-deploy.test.ps1で構築順序・CからDへのテーブル名受け渡し・失敗時の停止を確認。AWS/SAMと実行環境の存在確認用コマンドをモックして実施。
- C/DのYAMLの構文・参照・索引キー・Projectionを確認。元のmeasurementIdキーとRetainを維持。
- 作成したLambdaパッケージを直接読み込み、デモの配送一覧の次ページ、C共有例の92.5点を確認。

実行：npm run test:d、およびscripts/tests/dashboard-deploy.test.ps1。AWSへの通信・デプロイはテストに含まない。
